## Pièges Angelscript vus le 2026-11-17

1. `UFUNCTION(Server, Reliable)` : « Reliable » n'existe pas en Angelscript. Les RPC sont fiables par défaut ; seul `Unreliable` existe. Écrire `UFUNCTION(Server)` ou `UFUNCTION(Server, Unreliable)`.
2. Une fonction globale d'un fichier n'est pas visible d'un autre fichier : « Global function is declared in module ... can only be used in different script files if put in a namespace ». Mets-la dans un `namespace` et appelle `Espace::Fonction(...)`.
3. Un nom de surcharge script (`BlueprintOverride` d'un `BP_X` de la base C++) identique à celui d'une statique C++ NON-UFUNCTION de la base : l'appel `Instance.X(...)` se résout vers le C++ (« Function X is not BlueprintCallable or ScriptCallable and cannot be called from here »). Donne des noms distincts côté C++ (préfixe `Native`, p. ex. `NativeGetEscapeAction`) et garde `BP_X` pour la surcharge script.
4. Autres : une constante de fichier n'est pas visible d'un autre fichier ; les conteneurs imbriqués sont interdits (`TArray<TArray<...>>`, `TMap` de `TArray`...) ; un `float` script est un double, et un paramètre ref C++ `float&` veut un `float32` ; une méthode de classe script appelée directement comme argument de `T.AssertEquals` donne « Null pointer access » (affecte d'abord le résultat à une variable locale).
