## (2) Options (estimations, NON MESURÉES)
Le mode de mélange est une propriété du MATÉRIAU : changer pour A ou B s'applique à toutes les unités, même à opacité 1.0. Seul C ne change pas de passe.
- A, Masked + dither : OPACITY_MASK = (index 4 > bruit tramé, nœud DitherTemporalAA ou bruit écran), blend_mode BLEND_MASKED. Coût : test de pixel dans le prépasse de profondeur et les ombres, perte du Z précoce pour tous les dessins d'unité ; pas de tri, pas de surdessin supplémentaire, occlusion et ombres gardées (ombre criblée comme l'unité). Visuel : lisible, grain net sans TAA (anticrénelage du projet NON VÉRIFIÉ : la grep de `Config\DefaultEngine.ini` n'a rien rendu). Nanite : le Masked est accepté mais plus lent ; les unités de jeu sont des maillages à LODs Classic, pas Nanite. Couleurs 0-3 : intactes (la base color n'est pas touchée) ; l'opacité 1.0 doit laisser tous les pixels (à vérifier : pas de trous).
- B, Translucent : OPACITY = index 4. Un tri PAR COMPOSANT instancié, pas par instance : l'ordre interne des 2000 unités et des membres est arbitraire (artefacts de superposition) ; pas d'écriture de profondeur, donc brouillard (`M_FogPost`) et occlusion changent ; non éligible Nanite ; éclairage translucide différent (couleurs de joueur altérées) ; surdessin maximal en foule, passe translucide pour tout le monde. Pire coût et pire risque.
- C, teinte / désaturation : Base Color = Lerp(couleur, gris, (1 - index 4) x k). Une lecture de donnée et quelques opérations ; aucun changement de passe, d'ombre ni d'occlusion. Mais pas de transparence réelle : écart avec D824 Q3 B (« à demi transparentes »). Couleurs 0-3 : teinte gardée si k <= 0.5 environ.
- Ni A, B, ni C ne sont tranchés par D824 (GDD.md l.3606 : « ses propres unités dans la zone sont à demi transparentes », sans technique) : question écrite dans `Retours\Q-stealth-rendu.md` (recommandation A, sinon C ; défaut = rien de rendu).
