# CARTE-L2-PREUVES-1118 : preuves reseau AVEC EFFET des 16 ordres L2 (route script, hol.Rpc.OrderScript 1) - lecture seule, rien lance
Sources : Elrond (tip cdc2f53+), HOLPlayerController.cpp (C), Script\Net\HOLRpcPlayer.as (AS, hook ProofRoute l.452-546, RPC d'ordres l.1066+), rpc_routes_seats_run.ps1 (modele). Abreviations : S = journal serveur, K = journal du client vert.

## 0. Patron et regles communes (a lire avant les lots)
- Modele : rpc_routes_seats_run.ps1 (serveur dedie Plain, 2 sieges Human Alice slot 0 / Bob slot 1, `startingPeasants` 5, `-HOLCheats`, serveur SANS -ExecCmds, client rouge Bob = aucun appel -> 0 ligne `RpcOrder:` pour son siege, client vert Alice = `-ExecCmds="hol.Rpc.OrderScript 1,hol.Rpc.ProofRoute <bits>"`). Le script (`HOLRpcPlayer.as` Tick) execute les commandes 4 s apres le 1er tick du client, UNE FOIS. Pris : 1..16384 (surrender 16384 = DERNIER, ne jamais le combiner avec un ordre qui suit). Bits neufs : 32768 et suivants, un par ordre (P1 32768/65536/131072/262144, P2 524288/1048576/2097152/4194304, P3 8388608/16777216/33554432/67108864, P4 134217728/268435456/536870912/1073741824) ; la somme des 16 = 2^31 - 2^15 tient dans un int32 (GetInt). Alternative sans debordement : cvar `hol.Rpc.ProofOrders` (meme codage). Bits ajoutes AVANT la ligne `if ((Routes & 16384)...)` du hook.
- Ligne serveur de reception (script, toujours emise) : `RpcOrder: <nom> received by the server: slot N units U ...` ; noms : move, attack unit, heal unit, attack building, attack move, stop, toggle deploy, move in line, gather, place building, build units, drop off, garrison, ungarrison all, cancel building, set rally point. Refus : `RpcOrder: <nom> refused (<code>) for sender slot N`. Rouge commun (c) : le client rouge ne fait aucun appel -> `Select-String 'RpcOrder: '` sur le journal serveur filtre par `slot 1` = 0 ; et `RpcRoute: .* not sent` = absent (route reussie) avec cvar 1.
- `hol.Rpc.OrderTrace 1` (C++, serveur ET client, `-ExecCmds`) ajoute `OrderSend kind=<K> ...` (client) et `OrderRecv kind=<K> ...` (1re ligne de Do<X>, serveur) : preuve que Do<X> a ete atteint par le pont (meme ligne que la voie C++). Noms K : Move, AttackUnit, HealUnit, AttackBuilding, AttackMove, Stop, ToggleDeploy, MoveInLine, Gather, PlaceBuilding, BuildUnits, DropOff, Garrison, UngarrisonAll, CancelBuilding, SetRally.
- LACUNE du hook : tout part en un tir a +4 s et un ordre a effet (marche, recolte, garnison) a besoin d'ATTENTE. Ajouter au hook une liste d'etapes differees : une commande `@<secondes> <commande>` s'execute <secondes> apres le tir (machine dans le Tick, ~20 lignes script). Rapports de fin : `@12 hol.Units.Where 0` (positions, activite, charge, PV, cible : K, unites repliquees) et `@12 hol.Build.Report` (stock + batiments + progression). Le serveur n'a pas la ligne `Units where` sans -ExecCmds : on lit l'effet sur le client (units repliquees) et les lignes de simulation sur le serveur.
- Unites speciales (moine, deployable, soldats, garnison) : `hol.Units.Spawn` / `SpawnHere` sont serveur/solo. Script seul (0 C++) : cvar serveur `hol.Rpc.ProofSpawn` (Script\Net, nouveau fichier, Tick serveur, inerte a 0) qui execute `hol.Units.Spawn <n> <x> <y> <slot> <Type> <rayon>` (argument d'apres HOLCrossingTest.cpp:334, a relire) ; `hol.Cheat.SpawnBuilding <Type> <Slot> <Dx> <Dy>` (client, C.2030) donne un batiment fini gratuit.
- Pieges generaux : (1) l'expediteur est le SIEGE du client (Alice slot 0) : jamais d'ids ni de batiment de Bob dans l'ordre (le serveur ignore : `Move order of slot 0: N units ignored, not its own`, HOLUnitOrderProcessor.cpp:1235). (2) La cible doit exister cote client au tir (`hol.Select.Attack slot=1` prend le 1er unite de Bob connue ; batiment ennemi : FindMainCentre(enemy)). (3) `hol.Select.Own` AVANT tout ordre d'unites (GetCommandUnits). (4) Pas de projection ecran sous -nullrhi (non prouve) : `hol.Select.OrderGround/AttackMove/OrderLine/OrderSource/OrderNear/ClickGround` et `OrderAt` en dependent -> a eviter. (5) Ids d'un seul mode : ne pas melanger cvar 0 et 1 dans un scenario. (6) Le pilote A3 `OrderOrder` utilise `hol.Prod.Queue` comme BuildUnits : FAUX (c'est ServerQueueProduction, deja script) ; BuildUnits = unites envoyees sur un chantier (C.2871) : voir P3.

## Combien d'agents Sonnet (15 min, ~30 appels)
- C++ de preuve : 1 agent, 1 lot, 1 build : `hol.Units.AttackMove`, `OrderLine`, `AttackBuilding`, `Gather`, `DropOff`, `Build`, `Garrison`, `UngarrisonAll` + `hol.Prod.RallySite` (+ `hol.Build.CancelLast` si FindOwnBuilding refuse un chantier) = 8 a 10 commandes, ~120 lignes, UN fichier (HOLPlayerController.cpp, le fichier de C1 : apres sa fusion). Aucune de ces fonctions Request n'est BlueprintCallable : la commande console est la voie (un hook script ne peut pas les appeler).
- Script : 1 agent (HOLRpcPlayer.as : 16 bits + etapes `@s` + rapports ; `Script\Net\HOLRpcProofSpawn.as` nouveau, ProofSpawn serveur). Meme fichier que le hook : pas de second agent dessus.
- Outils : 2 agents en parallele (rpc_orders_p1p2_run.ps1, rpc_orders_p3p4_run.ps1, modele rpc_routes_seats_run.ps1, un `-Lot` par scenario, sortie `oui/NON` + VERDICT). Total 4 ; le script et les outils ne dependent pas du C++ pour P1 (Move, Stop), P2 (AttackUnit, HealUnit) et P3/P4 (PlaceBuilding, CancelBuilding, SetRally) : ces 7 preuves peuvent tourner des le build du lot C1/C2.
